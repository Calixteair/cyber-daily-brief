## Top 3 du jour

### 1. Check Point Security Gateway : deux CVE 9.8 en exploitation active depuis le 12 septembre (score 9/10)

Check Point a divulgue deux vulnerabilites pre-authentification de score CVSS 9.8 dans la gestion des certificats VPN de son Security Gateway. CVE-2026-85102 permet a un attaquant distant non authentifie d'executer du code arbitraire lors de la negociation VPN. Une seconde CVE 9.8 affecte le meme composant. L'exploitation est confirmee depuis le 12 septembre, les attaquants utilisant VPNs et proxies pour masquer leur origine. Le Dutch NCSC a emis une alerte le 10 septembre anticipant une exploitation imminente. Les appareils Spark (gamme PME de Check Point) sont particulierement cibles. La CISA a ajoute la faille au catalogue KEV avec une deadline de remediation le 25 septembre pour les agences federales americaines.

**Pourquoi c'est important :** Un RCE pre-auth CVSS 9.8 sur un firewall/VPN gateway constitue un incident notifiable sous NIS2 pour toute entite essentielle l'utilisant. L'exploitation active depuis deux semaines sans remediation generalisee illustre le gap entre patch publication et patch deployment que NIS2 cherche a resorber. Pour les entites couvertes par DORA (secteur financier), un acces VPN compromis peut qualifier d'incident operationnel majeur avec obligation de notification a l'ACPR. Les R81 et R81.10 en fin de support sont affectes mais ne recevront pas de patch standard.

**CVE :** CVE-2026-85102 (CVSS 9.8, pre-auth RCE VPN cert handling)
**Vendor :** Check Point

### 2. Brevo supply chain + ClickFix blockchain : 100 000 sites infectes via CDN (score 9/10)

La plateforme d'engagement client Brevo a ete victime d'une attaque supply chain sophistiquee : des attaquants ont vole une cle API Cloudflare pour deployer un Worker malveillant injectant des scripts ClickFix dans les pages des clients. En cinq heures et demie le 14 septembre, plus de 100 000 sites ont servi de faux CAPTCHA Cloudflare incitant les visiteurs a executer une commande malveillante. En parallele, une operation criminelle distincte exploite plus de 5 400 sites compromis pour livrer des payloads ClickFix stockes dans des smart contracts sur la BNB Smart Chain — une premiere technique d'evasion via blockchain.

**Pourquoi c'est important :** L'attaque Brevo illustre le risque de dependance a un tiers CDN : une seule cle API compromise suffit a empoisonner 100 000 sites clients. C'est precisement le scenario que le Cyber Resilience Act europeen (CRA) cherche a prevenir via les obligations SBOM et de gestion des dependances. L'utilisation de la blockchain comme infrastructure C2/payload delivery est une evolution tactique majeure : les URL de smart contracts ne peuvent pas etre takedown comme un serveur classique, ce qui complique la reponse defensive. Angle NIS2 : les entites essentielles utilisant des services CDN tiers doivent inclure ce risque dans leur analyse supply chain.

**Vendor :** Brevo (victime), Cloudflare (API compromise), BNB Smart Chain (infrastructure malveillante)
**Source :** [SecurityWeek](https://www.securityweek.com/brevo-supply-chain-attack-injects-malware-into-100000-websites/) | [BleepingComputer Brevo](https://www.bleepingcomputer.com/news/security/brevo-supply-chain-attack-injected-clickfix-scripts-on-customer-sites/) | [BleepingComputer ClickFix](https://www.bleepingcomputer.com/news/security/over-5-400-hacked-sites-serve-clickfix-payloads-stored-on-the-blockchain/)

### 3. MemTensor npm/PyPI compromis : GitHub Actions tokens voles pour injecter sckit (score 8/10)

Des acteurs inconnus ont compromis deux packages legitimes MemTensor sur npm et PyPI en volant les tokens de publication directement dans les pipelines GitHub Actions. Le mecanisme : des commits malveillants declenchaient le workflow CI/CD et exfiltraient les tokens npm/PyPI, permettant de publier des versions malveillantes des packages. La charge utile — un implant Go multiplateforme baptise sckit — cible Windows, Linux et macOS pour voler des identifiants. En parallele, un domaine CDN abandonne a ete re-enregistre par des acteurs malveillants alors que des milliers de sites l'appellent encore.

**Pourquoi c'est important :** L'attaque MemTensor illustre une evolution des techniques supply chain : compromettre les pipelines CI/CD plutot que les packages directement. La protection des secrets dans GitHub Actions (tokens npm, PyPI, Docker Hub) devient un enjeu critique de securite DevOps. Le Cyber Resilience Act impose aux editeurs de signer leurs artefacts — si cette pratique avait ete generalisee, la substitution malveillante aurait ete detectable. L'angle "domaine CDN abandonne" rappelle que la gestion du cycle de vie des dependances (desactivation, monitoring) est aussi importante que le patching.

**Vendor :** MemTensor (victime), npm, PyPI, GitHub Actions

## Trends emergents observes

1. **La blockchain comme infrastructure offensive** — Le stockage de payloads ClickFix dans des smart contracts BNB est une innovation tactique significative : les smart contracts sont immuables et leur contenu ne peut pas etre supprime ou saisi par des autorites. Cela pose un defi nouveau pour les capacites de takedown et oblige les defenses a operer a la couche applicative plutot que sur l'infrastructure. Tendance a surveiller dans les prochains frameworks ATT&CK.

2. **Compromission des pipelines CI/CD comme vecteur supply chain de premier ordre** — L'attaque MemTensor via GitHub Actions illustre que les pipelines CI/CD sont devenus une surface d'attaque majeure. Voler un token de publication dans un workflow est plus simple et plus furtif que de compromettre un mainteneur. La separation des privileges dans les pipelines (permissions minimales, OIDC au lieu de secrets longue duree) devient une exigence de securite fondamentale.

3. **ClickFix comme technique social engineering dominant de l'automne 2026** — ClickFix (fausse page CAPTCHA invitant a coller une commande PowerShell/terminal) est maintenant leveragee par des acteurs distincts dans des contextes tres differents : supply chain CDN (Brevo), sites compromis locaux (Ukraine), blockchain delivery. Cette convergence suggere une maturation et une democratisation de la technique dans les kits criminels.

4. **Equipements reseaux en fin de support : le talon d'Achille des entites NIS2** — Les Check Point R81/R81.10 en fin de support sont affectes par CVE-2026-85102 sans patch standard disponible. C'est un scenario NIS2 direct : une entite essentielle ne peut pas patcher parce que son equipement est EOL. La gestion du cycle de vie des actifs et les budgets de renouvellement des equipements reseaux deviennent un enjeu de conformite, pas seulement technique.

5. **RGPD enforcement : les amendes restent modestes mais s'accumulent** — La Suede sanctionne Miljodata 183 000 dollars pour une breach de 2,2 millions de personnes. L'amende est symboliquement faible (0,008% du plafond theorique maximal), mais la regularite de ces decisions dans plusieurs pays europeens cree une pression cumulative sur la maturite des processus de securite des PME.

### Draft LinkedIn — GitHub Actions comme vecteur supply chain : la nouvelle frontiere (score 8/10)

> Les attaquants n'ont pas compromis le compte du mainteneur. Ils n'ont pas piraته son ordinateur. Ils ont simplement pousse des commits qui ont convaincu le pipeline CI/CD de leur remettre les cles.
>
> C'est la technique utilisee dans l'attaque MemTensor cette semaine : des acteurs malveillants ont compromis les packages npm et PyPI de MemTensor en volant les tokens de publication directement dans les workflows GitHub Actions. Resultat : un implant Go multiplateforme distribue a tous les utilisateurs du package comme une mise a jour legitime.
>
> Ce qui rend cette attaque particulierement instructive, c'est qu'elle cible une hypothese implicite de securite : "si le code est dans mon repo GitHub, il est sous mon controle". Ce n'est plus vrai quand votre pipeline CI/CD dispose de permissions excessives et que les secrets de publication ne sont pas scopes.
>
> Les bonnes pratiques qui auraient prevenu cette attaque :
> 1. Utiliser l'OIDC federation plutot que des secrets longue duree pour npm/PyPI
> 2. Appliquer des permissions minimales dans chaque job GitHub Actions
> 3. Activer la signature des releases (sigstore/cosign) pour que les utilisateurs puissent verifier l'integrite
> 4. Proteger les branches de production avec des regles strictes et des reviewers obligatoires
>
> En tant qu'etudiant en cyber avec une sensibilite DevSecOps, je pense que la securite des pipelines CI/CD va devenir une specialite a part entiere dans les prochaines annees. Le CRA va l'imposer aux editeurs europeens. Les startups et scale-ups qui l'anticipent maintenant auront une longueur d'avance.
>
> #Cybersecurite #DevSecOps #SupplyChain #GitHubActions #SBOM #CRA #npm #AlternanceCyber

> - La detection comportementale des acces blockchain depuis des endpoints enterprise va devenir un signal pertinent
>
