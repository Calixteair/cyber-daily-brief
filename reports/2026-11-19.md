# Veille cyber — 2026-11-19

_Analyste : Claude (agent planifié) pour Calixte — ESIEA 4A, alternant cyber governance_
_Fenêtre : dernières 24 h_

## Statut de la collecte

**Collecte impossible — domaines sources bloqués par la politique réseau de la session cloud.**

Toutes les tentatives de fetch RSS ont échoué avec un refus 403 du proxy sortant :

| Source | Domaine | Statut |
|---|---|---|
| The Hacker News | feeds.feedburner.com | BLOQUÉ (403) |
| BleepingComputer | www.bleepingcomputer.com | BLOQUÉ (403) |
| Krebs on Security | krebsonsecurity.com | BLOQUÉ (403) |
| Dark Reading | www.darkreading.com | BLOQUÉ (403) |
| Hacker News API | hacker-news.firebaseio.com | BLOQUÉ (403) |
| NVD NIST | nvd.nist.gov | BLOQUÉ (403) |

La commande `curl -sS "$HTTPS_PROXY/__agentproxy/status"` confirme que le proxy est actif (`selective: false`) mais refuse les connexions sortantes vers ces domaines avec `connect_rejected`.

## Problème persistant

Ce blocage est identique aux jours précédents (voir rapports du 2026-11-17 au 2026-11-18). La veille automatique est non fonctionnelle tant que les domaines ne sont pas autorisés.

## Action requise

Pour débloquer la veille, il faut autoriser les domaines suivants dans la politique réseau de l'environnement cloud de la session. Voir la documentation : https://code.claude.com/docs/en/claude-code-on-the-web (section "Network policy" / "Egress domains").

Domaines à autoriser :

- `feeds.feedburner.com`
- `www.bleepingcomputer.com`
- `krebsonsecurity.com`
- `www.darkreading.com`
- `hacker-news.firebaseio.com`
- `nvd.nist.gov` (optionnel, pour les CVE NIST)
